Инструкция по разделению React-компонентов (API → Models → Hooks → Components)

Цель:
Разделять ответственность между слоями, чтобы код был проще поддерживать и 
тестировать. Нижние слои ничего не знают о верхних (Никаких импортов).

Правило зависимостей:
Component
   ↓
Hook (ViewModel)
   ↓
Model
   ↓
API

API:
- Только HTTP-запросы.
- Не содержит React, JSX, useState.

Models:
- Бизнес-логика.
- React Query/Zustand/Redux.
- Преобразование данных.
- Не содержит JSX.

Hooks:
- Собирают несколько моделей.
- Готовят данные и обработчики для UI.
- Не рисуют интерфейс.

Components:
- Только отображение.
- Минимум логики.
- Не обращаются напрямую к API.

Чек-лист:
- Делает HTTP-запрос → API
- Хранит состояние → Model
- Объединяет несколько моделей → Hook
- Рисует JSX → Component

Рекомендуемая структура:
src/
 ├── api/
 ├── models/
 ├── hooks/
 └── components/

Пример потока:
UsersPage
  ↓
useUsersPage()
  ↓
useUsersModel()
  ↓
getUsers()
  ↓
Backend

Антипаттерны:
- Компонент вызывает fetch/axios.
- API использует React Hooks.
- Model содержит JSX.
- Бизнес-правила находятся в компоненте.

Практический алгоритм:
1.  Выделить JSX.
2.  Вынести запросы в API.
3.  Вынести состояние и бизнес-логику в Models.
4.  Создать Hook, объединяющий модели.
5.  Оставить компонент декларативным.

Признаки хорошей архитектуры:
- Компонент помещается на одном экране. (30-50 строк, 80-120 символов)
- JSX читается сверху вниз.
- Бизнес-логика не дублируется.
- API можно заменить без изменения UI.
