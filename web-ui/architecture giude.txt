Инструкция по разделению React-компонентов (API → Models → Hooks → Components)

Цель

Разделять ответственность между слоями, чтобы код был проще поддерживатьи тестировать.

Правило зависимостей

Component
   ↓
Hook (ViewModel)
   ↓
Model
   ↓
API

Нижние слои ничего не знают о верхних.

API

Только HTTP-запросы.

Не содержит React, JSX, useState.

Models

Бизнес-логика.

React Query/Zustand/Redux.

Преобразование данных.

Не содержит JSX.

Hooks

Собирают несколько моделей.

Готовят данные и обработчики для UI.

Не рисуют интерфейс.

Components

Только отображение.

Минимум логики.

Не обращаются напрямую к API.

Чек-лист

Если код...

Делает HTTP-запрос → API

Хранит состояние → Model

Объединяет несколько моделей → Hook

Рисует JSX → Component

Рекомендуемая структура

src/
 ├── api/
 ├── models/
 ├── hooks/
 └── components/

Пример потока

UsersPage
  ↓
useUsersPage()
  ↓
useUsersModel()
  ↓
getUsers()
  ↓
Backend

Антипаттерны

Компонент вызывает fetch/axios.

API использует React Hooks.

Model содержит JSX.

Бизнес-правила находятся в компоненте.

Практический алгоритм

Выделить JSX.

Вынести запросы в API.

Вынести состояние и бизнес-логику в Models.

Создать Hook, объединяющий модели.

Оставить компонент декларативным.

Признаки хорошей архитектуры

Компонент помещается на одном экране.

JSX читается сверху вниз.

Бизнес-логика не дублируется.

API можно заменить без изменения UI.
